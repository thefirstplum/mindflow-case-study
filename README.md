# MindFlow 개발 기록

개인용 메모/마인드맵/캘린더 PWA를 Claude Code와 같이 4개월 가까이 만들면서 남긴 기록이다.
앱 소개보다는 AI가 짠 코드를 어떻게 관리했는지를 적었다.

- 앱 코드: https://github.com/thefirstplum/mindflow
- 라이브: https://thefirstplum.github.io/mindmap-flow/

처음엔 바이브 코딩으로 시작했다. 2주 정도는 잘 굴러갔는데 3주쯤 되니 세션마다 같은 문제를 다르게 풀고 있었다.
같은 의미의 아이콘이 화면마다 달랐고, 비슷한 기능이 두 군데 생겼고, 예전에 왜 그렇게 짰는지 나도 AI도 몰랐다.
그 뒤로 CLAUDE.md 규칙, 검증 절차, 커밋 본문 형식을 하나씩 붙여 가며 진행했다.

## 요약

- 버그는 "고쳐줘" 대신 원인 경로부터 찾게 했다
- 검증 방법을 요청에 같이 적고, 데이터를 건드리는 수정은 개수를 직접 셌다
- 커밋 본문과 주석을 다음 세션용 인수인계 문서로 썼다
- 같은 실수가 반복되면 CLAUDE.md에 날짜와 함께 규칙으로 남겼다

## 버그를 맡기는 방식

"동기화 실패 뜨는 거 고쳐줘"라고 하면 AI는 실패 표시를 안 뜨게 만드는 쪽으로 간다.
그래서 "실패 표시가 켜지는 코드 경로를 전부 찾아서 각 분기가 성립하는 조건을 나열해줘"처럼 원인 경로부터 찾게 했다.

동기화 실패 건([발췌 6](code/06-silent-token-refresh.js))은 이렇게 해서 원인이 셋 겹친 걸 알았다.
만료가 임박하면 갱신 타이머가 아예 안 잡히는 분기, iOS PWA 백그라운드에서 setTimeout이 안 도는 문제,
15초 폴링이 갱신 시도 없이 바로 error를 찍는 코드. 하나만 고쳤으면 빈도만 줄었을 것이다.

## 검증

AI가 "테스트했습니다"라고 하는 건 믿지 않았고, 요청할 때 검증 방법을 같이 적었다.

- 날짜 계산처럼 입출력이 분명한 로직은 함수를 떼어내 node로 경계값을 돌렸다.
- 데이터를 건드리는 수정은 실제 데이터를 셌다. 한글 NFD 건에서는 메모 49개를 전부 검사해 NFD 제목 19개를 찾았고,
  수정 후 백업과 비교해 본문 49개는 그대로, 제목 19개만 바뀐 걸 확인했다. AI가 "아마 몇 개"라고 하면 세는 코드부터 짜게 했다.
- 빌드가 없어서 문법 오류나 전역 이름 충돌을 잡아주는 게 없다. 작업 끝에 아래 정도는 돌리고 브라우저에서 콘솔을 봤다.

```bash
for f in js/*.js; do node --check "$f"; done
# 전역 심볼 중복 정의 (모듈이 없어서 제일 자주 터짐)
for f in js/*.js; do grep -oE "^(function|const|let) [A-Za-z0-9_]+" "$f"; done | sort | uniq -d
```

## 커밋 본문과 주석

다음 세션은 이번 대화를 모르니까 커밋 본문과 주석이 인수인계 역할을 한다. 본문은 [규약], [증상], [수정], 검증 순으로 썼다.

```
fix(gcal): 종일 일정이 만들어지지 않던 문제 — end.date 미포함 규약

[규약] Google Calendar의 종일 일정 end.date는 '미포함(exclusive)'이다.
[증상] 입력값을 그대로 보내 start==end가 되어 길이 0짜리 일정이 만들어졌다.
       표시 조건이 `start <= day < end`라 어떤 날에도 안 걸려 영원히 안 보였다.
[수정] _gcalShiftDateStr / _gcalShiftDays 헬퍼 추가 ...
검증(순수 함수 재현): 하루짜리가 해당 날에만 / 3일짜리가 정확히 3일 /
편집 왕복 시 원래 입력값 복원 / 월말 경계(7/31 → 8/1) / 종료일 공백 보정.
```

주석에는 하면 안 되는 걸 주로 적었다. 예를 들어 타이머 렌더 쪽에는 "여기서 innerHTML 쓰면 매초 DOM을 갈아엎는다",
상태 저장 쪽에는 "save()가 드라이브 동기화를 예약하니까 매초 부르지 말 것"을 적어 뒀다. 둘 다 한 번 겪은 버그다.

## CLAUDE.md

세션 시작 때 자동으로 읽히는 파일이라 규칙은 여기 모았다. 미리 설계한 건 아니고 뭔가 깨질 때마다 추가했다.

어느 세션에서 AI가 첨부 파일 링크에 타입별로 📄📊🎬 같은 이모지를 붙였고, 다음 세션은 그 매핑을 모르고 또 다른 이모지를 골랐다.
되돌리면서 이렇게 적었다.

```markdown
### 3-1. ❌ 금지 — 파일 타입별 이모지 다양화
메모 본문에 삽입되는 마크다운 링크는 모든 파일에 동일 표지자(📎) 사용.
파일 타입별로 📄📝📊🗜️🎬🎵📃⚙️🌐📜 다양화하면 일관성 깨짐 (해본 적 있음, 2026-05-29 revert).
```

"해본 적 있음"과 날짜가 없으면 다음 세션이 더 나은 UX라고 보고 다시 시도한다.
그 밖에 "빌드 시스템 없음: 바닐라 JS, deferred script 순서 의존" 한 줄이 있는데, 이게 없으면 AI가 기본으로 import/export를 써서 앱이 안 뜬다.
규칙은 새로 만들거나 고치는 코드부터 적용하게 했다. 기존 50여 곳을 한 번에 바꾸라고 하면 그 와중에 다른 게 깨진다.

## 주요 결정

- 동기화 재설계 (5/8): Gist 기반 함수 하나를 백업/클라이언트/어댑터/엔진/이벤트 5개 계층으로 나눴다. 백업 계층을 제일 먼저 만들었다. 충돌이 나면 덮어쓰지 않고 사본을 남긴다.
- OAuth PKCE 전환 (5/13): implicit flow라 한 시간마다 로그인 팝업이 떴다. Cloudflare Worker에 refresh_token을 두고 만료 5분 전에 갱신한다.
- 마인드맵 머지 (5/28): Yjs 같은 CRDT 라이브러리는 번들러가 필요해서 안 썼다. 노드/엣지 단위로 병합 규칙을 따로 정했다.
- IndexedDB 전환 (5/28): `load()`/`save()`를 동기 그대로 두고 utils.js 안에서 캐시/IDB/localStorage를 처리했다. 호출처는 안 고쳤다.
- 기능 삭제 (8/3): 가계부/루틴(-1,144줄)과 열 방법이 없던 페이지 2개(-669줄)를 지웠다. 가계부는 저장 데이터에 키가 아예 없었고 루틴은 두 달 넘게 기록이 없었다. 지우기 전에 루틴 설정은 JSON으로 백업했다.
- 감정일기 흡수 (8/4): 따로 저장하던 일기를 일반 메모(.md)로 옮겼다. 2주 뒤 집중 타이머도 같은 방식으로 기록을 메모에 쌓는다.

자세한 건 [docs/03-decisions.md](docs/03-decisions.md).

## 메모 앱을 작업 로그로

이 앱은 메모를 Google Drive에 .md로 저장한다. 그래서 다른 프로젝트의 Claude Code 세션이 끝날 때 같은 폴더에 작업 기록을 .md로 남기게 했다.
폰에서 그 메모를 열어 `## 코멘트`에 다음 지시를 적어 두면, 다음 세션이 시작할 때 최근 기록 3개를 읽고 반영한다.
새로 짠 코드는 없고 기존 동기화와 태그 기능을 그대로 썼다. 규약과 그게 생긴 사고들은 [docs/04-agent-loop.md](docs/04-agent-loop.md).
