# 의사결정 기록

판단이 갈렸던 커밋만 추렸다. 날짜는 커밋 날짜, 인용은 커밋 본문이다.

## 동기화 5계층 (2026-05-08)

Gist 기반 함수 하나로는 기기 두 대를 못 버텼다. BackupService / DriveClient / ItemAdapters / SyncEngine / SyncEvents로 나눴고,
갈아엎는 동안 데이터를 잃지 않으려고 BackupService(push/pull 직전 IndexedDB 스냅샷 10개)를 먼저 만들었다.
충돌이 나면 `(충돌 MM-DD HH:mm)` 사본을 만들고 `#conflict` 태그를 붙인다. 어느 쪽도 덮어쓰지 않는다.

## OAuth PKCE (2026-05-13)

implicit flow는 access token만 줘서 한 시간마다 팝업이 떴다. Cloudflare Worker가 refresh_token을 KV에 보관하고 브라우저는 만료 5분 전에 갱신한다.
7월의 토큰 오탐 수정(발췌 6)도 이 구조 위에서 했다.

## CRDT 라이브러리 대신 노드 단위 머지 (2026-05-28)

Yjs/Automerge는 번들러가 필요하고, 다룰 건 노드 배열과 엣지 배열뿐이었다. 필드별 병합 규칙을 따로 정했다(발췌 3).
순수 add-wins면 지운 노드가 되살아나는데 사용자에겐 버그라서, tombstone이 더 최신이면 삭제를 유지한다.

## IndexedDB 전환 (2026-05-28)

localStorage 5MB 초과. `load()`/`save()`를 async로 바꾸면 전 파일 수정이라 동기 시그니처를 유지했다.
utils.js 안에서 메모리 캐시가 동기 응답을 맡고, 직접 `localStorage.setItem`을 부르던 52곳은 `Storage.prototype` 패치로 받았다(발췌 4).

## 기능 삭제

- 가계부/루틴 (2026-08-03, -1,144줄): "가계부는 동기화 데이터에 ledger 키 자체가 없고 탭도 숨김 상태였다. 루틴은 5개 설정이 있었으나 체크 기록이 3일치, 마지막이 2026-05-26". 루틴 설정은 지우기 전에 JSON으로 백업했다. grep으론 123건이었지만 실제 심볼 참조는 18곳이었다.
- 도달 불가 페이지 2개 (2026-08-03, -669줄): 루틴을 지운 뒤 같은 패턴을 찾다가 발견. 열 방법이 없는데 `renderTimeBlocks`가 캘린더 렌더마다 불리고 있었다.
- 데일리노트 (2026-05-28): 붙이고 30분 남짓 만에 되돌렸다. 캘린더, 감정일기와 역할이 겹쳤다.
- CSS 재작성 (2026-04-30): 7,994줄에서 2,076줄, `!important` 1,048개에서 15개. 이후 다시 늘어 8월 기준 6,447줄이다.

## 감정일기를 메모로 (2026-08-04)

`journal.json`에 따로 있던 일기를 일반 메모(제목 `YYYY-MM-DD 일기`, 태그 `일기`)로 옮겼다. 검색, 태그, Drive 백업이 따로 작업 없이 붙는다.
기존 9개를 옮길 때 수정일은 원래 날짜로 두고 원본 localStorage는 남겼다. 8월 16일 집중 타이머도 같은 방식으로 `YYYY-MM-DD 집중` 메모에 기록한다.

## 고치지 않고 남긴 것 (2026-07-31)

NFD 검색 수정 커밋 끝에 적은 내용이다. 같이 고치면 검증 범위가 커져서 기록만 했다.
