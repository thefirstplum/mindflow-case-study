# 메모 앱을 작업 로그 저장소로 쓰기

프로젝트가 여러 개가 되니 CLAUDE.md만으로는 "지난주에 어디까지 했지", "다음에 하자던 게 뭐였지"가 관리되지 않았다.
노트 앱에 적으면 AI가 못 읽고, CLAUDE.md에 적으면 폰에서 못 본다.

이 앱은 메모를 Google Drive 폴더에 .md로 저장하고 있어서 그 폴더를 같이 쓰기로 했다.

1. 각 프로젝트의 Claude Code 세션이 끝날 때 그 폴더에 기록 .md를 만든다.
2. Drive가 동기화하면 폰의 MindFlow에 메모로 뜬다.
3. 폰에서 메모의 `## 코멘트`에 다음 지시를 적는다.
4. 다음 세션은 시작할 때 해당 프로젝트 태그가 붙은 최근 기록 3개를 읽고 코멘트부터 반영한다.

앱 쪽 코드는 새로 짜지 않았다. 각 프로젝트 CLAUDE.md에 아래 규약을 붙였을 뿐이다.

````markdown
### ② 세션 종료 — 기록 생성
반드시 새 파일을 만든다. 기존 파일은 절대 수정·삭제하지 않는다.

---
id: {17자리 ID}
title: [{{프로젝트}}] {이번 세션 한 줄 제목}
tags: ["프로젝트/{{프로젝트}}"]
---

{한 줄 요약 — 반드시 첫 줄에}

## 이번 세션
- {한 일}

## 다음
- [ ] {다음에 할 일}

## 코멘트

#프로젝트/{{프로젝트}}
````

## 규칙마다 이유

기존 기록은 고치지 않고 새 파일만 만든다. AI가 기존 기록을 "업데이트"하면 폰에서 쓴 코멘트가 날아가고 동기화 충돌이 난다.
ID를 17자리로 한 건 앱의 `newMemoId()`와 같은 `Date.now()*10000 + random` 방식을 써서 앱에서 만든 메모와 겹치지 않게 하려는 것이다.

첫 줄에 요약을 쓰게 한 건 앱 목록과 홈 카드가 첫 줄을 미리보기로 쓰기 때문이다. `##`로 시작하면 목록에서 알아볼 수 없다.
`## 다음`은 체크박스로 적는다. 홈의 "오늘의 할 일"과 프로젝트 진행률이 `- [ ]`/`- [x]`만 센다.

본문 끝 해시태그는 겪고 나서 넣었다. 앱은 본문 `#태그`를 기준으로 tags를 다시 계산하는데(`syncMemoHashtags`), 프론트매터에만 태그를 쓴 기록은 폰에서 코멘트를 한 글자 치는 순간 프로젝트에서 빠졌다(`fix(docs): 에이전트 지시문 — 본문 인라인 해시태그 필수로`, 2026-07-30).

그 밖에 `## 코멘트`는 사람이 쓰는 칸이라 비워 두게 했고, 태그 이름은 표에 있는 것만 쓰게 했다. AI가 이름을 지으면 `프로젝트/블로그`, `프로젝트/블로그앱`처럼 갈라진다.

형식 규칙 대부분이 앱이 그 메모를 어떻게 읽는지에 묶여 있다. "요약을 쓰라"보다 "안 쓰면 목록에서 이렇게 보인다"고 적었을 때 더 잘 지켰다.
